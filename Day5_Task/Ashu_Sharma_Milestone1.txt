## SECTION A — PROBLEM STATEMENT

This pipeline processes a PDF document through five connected stages: Ingest, Structure, Store, Summarise, and Visualise. During the Ingest stage, text is extracted from all pages of the PDF using PyMuPDF. The extracted text is then passed to the Structure stage, where it is converted into a pandas DataFrame containing useful metadata such as page numbers, word counts, and text previews. In the Store stage, the structured data is saved as CSV and JSON files for future analysis. The Summarise stage uses the Groq API and an LLM to generate a concise summary of the document. Finally, the Visualise stage creates a bar chart showing word counts per page, helping users quickly understand document content distribution.

## SECTION C — CODE BLOCKS

### C1. LOGGING SETUP

import logging

### C2. INGEST + EXTRACT

```python
import fitz

pdf_path = "./data/report.pdf"

doc = fitz.open(pdf_path)

page_texts = []

for page_num in range(len(doc)):
    page = doc.load_page(page_num)
    text = page.get_text()
    page_texts.append(text)

doc.close()

print(f"Extracted text from {len(page_texts)} pages")
```

### C3. STRUCTURE

```python
import pandas as pd

records = []

for idx, text in enumerate(page_texts, start=1):
    records.append({
        "page_no": idx,
        "word_count": len(text.split()),
        "first_50_chars": text[:50]
    })

df = pd.DataFrame(records)

print(df.head())
```

### C4. STORE

```python
import os

os.makedirs("output", exist_ok=True)

df.to_csv("output/pages.csv", index=False)

df.to_json(
    "output/pages.json",
    orient="records"
)

print("Structured data saved successfully")
```

### C5. SUMMARISE WITH GROQ

```python
import os
from groq import Groq

client = Groq(
    api_key=os.environ["GROQ_API_KEY"]
)

combined_text = "\n".join(page_texts)

prompt_text = (
    "Summarise this in exactly 3 bullet points.\n\n"
    + combined_text[:2000]
)

response = client.chat.completions.create(
    model="llama-3.1-8b-instant",
    messages=[
        {
            "role": "user",
            "content": prompt_text
        }
    ]
)

print(response.choices[0].message.content)
```

### C6. VISUALISE

```python
import matplotlib.pyplot as plt

plt.figure(figsize=(8, 5))

plt.bar(
    df["page_no"],
    df["word_count"]

plt.title("Word Count per PDF Page")
plt.xlabel("Page Number")
plt.ylabel("Word Count")

plt.show()
```

## SECTION D — EXPECTED GROQ RESPONSE SHAPE

The Groq API call will generate a concise summary containing exactly three bullet points.

* The first bullet will likely describe the primary topic or objective of the document.
* The second bullet will summarize important findings, insights, or observations.
* The third bullet will highlight conclusions, recommendations, or key takeaways.

The response should be short, structured, and easy to read.

## SECTION E — LESSONS LEARNED

This assignment demonstrated how a complete document-processing workflow can be built by integrating PDF extraction, structured data storage, large language models, and data visualization. The pipeline successfully transformed unstructured PDF content into organized datasets and generated meaningful summaries using an LLM. One challenge was coordinating multiple libraries and ensuring smooth data flow between stages. Another difficulty was designing prompts that would consistently produce useful summaries. In a production environment, I would incorporate an MLOps practice such as automated monitoring and logging. This would help track pipeline health, identify failures early, improve observability, and ensure reliable operation as the system scales.
